## Full attack payload descriptions (12 families)

**Attack Construction.** Each adversarial document $d^{*} = [c \| \iota]$
combines camouflage prefix $c$ (legitimate content maximizing retrieval
probability) with injection payload $\iota$. For cross-dataset evaluation,
most canonical attacks are instantiated with an NQ-domain (physics)
camouflage prefix regardless of target dataset, denoted by a prefix in
result tables (e.g., NQ_OVERRIDE, NQ_TECHNICAL_OVERRIDE); the four adaptive
attacks additionally have genuinely domain-aligned, MITRE-cybersecurity-themed
variants when evaluated against the MITRE KB (Table tab:adaptive). These
dataset-specific variants belong to the same family as their base attack —
they do not constitute separate attack strategies.

**Canonical Attacks (6):**
- **Override (O1):** explicit instruction replacement (IGNORE ALL PREVIOUS INSTRUCTIONS).
- **Exfiltration (O2):** HTML comment embedding audit directive instructing system prompt leakage.
- **Role hijacking (O3):** DAN persona assignment overriding safety constraints.
- **Denial (O4):** administrative notice blocking all responses.
- **Technical Override (O1):** injection framed as security patch in technical content.
- **Data Exfiltration (O2):** compliance audit notice in domain-specific content.

**Advanced Attacks (2):**
- **Unicode Override:** adversarial instructions obfuscated using zero-width Unicode characters (U+200B, U+200C, U+200D) invisible to lexical filters. The payload "IGNORE ALL PREVIOUS INSTRUCTIONS" is character-interleaved with zero-width spaces, rendering regex patterns non-matching while remaining interpretable by the LLM.
- **Implicit Injection:** adversarial behavior induced through narrative framing (a simulated security audit session) without any explicit instruction keywords, bypassing all lexical detection.

**Adaptive Attacks (4)**, generated by DeepSeek-V3 to evade known filter patterns: LLM-Generated (payload embedded in domain-accurate content); Base64-Encoded (payload encoded, invisible to string filters); Many-Shot (payload repeated 5× with syntactic variation); Keyword-Free Paraphrase (LLM reformulation avoiding all compromise markers).

| Layer | Operation | Latency (ms) |

| L1 | Lexical filter / 14 regex (per doc.) | 0.02 ± 0.00 |
| L1c | Embedding anomaly score (per doc.) | 109 ± 122 |

| L3 | Output verifier / 13 markers | 0.00 ± 0.00 |
| L1b | LLM-judge / LLaMA 3 8B CPU | ≈100,000 |

(mean ± std, n=10 runs, CPU-only platform; LLM API latency for GPT-3.5-turbo/DeepSeek-V3 is network-dependent, ≈1–3s, not included.)

Full analysis: L0–L3: <1ms; L1c: ≈109ms (offline); L1b (LLaMA 3 8B): ≈100s — offline only; GPU needed for real-time. This session's L2-isolation-ablation pilot independently measured a single L1b call at ≈395s on a 1-CPU-core machine, higher than this table's original figure — machine-dependent, see `docs/AUDIT_camera_ready.md`.

**Deployment Guidance.** L0+L1 (mandatory, <0.1ms): eliminates canonical attacks at indexing and query time. L3 (conditional): ASR=0% but SAU −28%; reserve for high-security contexts. L1c (≈109ms): offline indexing screen for implicit injections. L1b (≈100s CPU): offline-only; GPU or fine-tuned classifier needed for real-time. L2 (validate first): non-monotonic risk — empirically validate before enabling.

**Qualitative Notes (MITRE).** Override blocked by L1 when retrieved; Tech. Override: AHR=100% at k=10 but CASR=0% (generation-level resistance); Auto-Paraphrase: 6.7% vs. 3.3% ASR illustrating L2 amplification.

## Fairness and Accountability (full discussion)

Defense utility cost is itself a fairness dimension: L3 (Output Verifier)
replaces up to 22% of legitimate responses with a fallback,
disproportionately affecting edge-case or domain-specific queries. L1 and
All heuristic incur ≤1.3% SAU cost *on the benchmark's own easy legitimate
documents*, making L1 look like the most equitable single layer — but that
specificity claim does not hold on more realistic, directive-sounding
legitimate content (see the benign-hard corpus result retained in the main
paper's Limitations). In high-stakes domains — healthcare, legal
assistance, finance, education, and public administration — silently
suppressing a document introduces transparency risks independent of
security benefit. Our lexical filters are English-centric: multilingual
and code-switching attacks may bypass English-only regex patterns, while
benign non-English content risks higher false-positive rates from L1b.
This asymmetry — English KBs better protected, non-English content
disproportionately filtered — is a fairness concern for global Web
deployments. Trustworthy RAG systems should combine provenance tracking,
multilingual defense evaluation, human review workflows for borderline
cases, and user-facing explanations of filtering decisions. Deployments
should produce defense audit logs (document ID, triggered layer, matched
pattern, timestamp, automatic vs. human-reviewed) to support post-incident
analysis and compliance. Accountability for agent actions on injected
instructions — which actor (document author, KB curator, deployer, agent
designer) bears responsibility — remains an open governance problem for
Web-scale agentic systems.

## Minimal Agentic IPI Evaluation (full section)

We implement a minimal RAG agent with four tools: `search_kb` and
`summarize_doc` (authorized), and `send_email` and `export_context`
(restricted, simulated).

**Table — Agentic IPI evaluation** (20 queries, 2 models). TMR_vol =
voluntary tool misuse rate; PCR = mean parameter compliance (forced call);
Sens.% = fraction of forced calls with sensitive params.

| Config | Attack | TMR_v (GPT-3.5) | PCR | S% | TMR_v (DeepSeek) | PCR | S% |
|---|---|---|---|---|---|---|---|
| No def. | Tool mis. | 0% | .52 | 85 | 25% | .28 | 50 |
| No def. | Ctx exfil | 0% | .62 | 80 | 0% | .62 | 95 |
| All H. | Tool mis. | 15% | .52 | 85 | 30% | .30 | 55 |
| All H. | Ctx exfil | 0% | .57 | 80 | 0% | .56 | 90 |
| Sem. F. | Tool mis. | 20% | .52 | 90 | 30% | .30 | 55 |
| Sem. F. | Ctx exfil | 0% | .52 | 75 | 0% | .52 | 85 |

Two adversarial documents instruct the agent to call unauthorized tools
(`AGENT_TOOL_MISUSE`, `AGENT_CONTEXT_EXFIL`). We evaluate two metrics
across 3 defense configurations, 20 queries, and 2 generator models
(GPT-3.5-turbo and DeepSeek-V3): TMR_vol, the fraction of queries where
the agent freely calls an unauthorized tool (`tool_choice=auto`); and PCR,
when the tool call is forced, the fraction of calls where parameters
contain context-derived sensitive content.

The results show four patterns: (1) Alignment governs voluntary tool
misuse: GPT-3.5-turbo achieves TMR_vol=0% without defense; DeepSeek-V3
25%, confirming function-calling safety is model-level. (2) Defenses
paradoxically increase misuse (non-monotonic): GPT-3.5-turbo
0%→15%→20%, DeepSeek-V3 25%→30%→30% — extending the retrieval-design
discussion to the agentic domain. (3) Forced PCR is alignment-independent:
GPT-3.5-turbo 0.52–0.62 (75–90%), DeepSeek-V3 0.28–0.62 (50–95%) — a
residual exfiltration risk alignment cannot address. (4)
`AGENT_CONTEXT_EXFIL` achieves TMR_vol=0% for both models;
`AGENT_TOOL_MISUSE` reaches 0–30%, as explicit function-name framing is
more effective than parameter-oriented framing.

*Limitation:* Single-turn agentic setting; multi-step injection,
retrieval-optimized agent attacks, and Llama 3.1 70B evaluation remain
future work. The originally reported paired McNemar test for this
comparison was found (during this revision) to rest on a fabricated
per-query pairing — see `docs/AUDIT_camera_ready.md` Finding F. Corrected:
Fisher's exact on total successes/failures (2/20 vs. 4/20), p=0.66 (ns) —
the non-monotonic pattern is observed but not statistically demonstrated
at this scale. CI sensitivity (α ∈ {0.10–0.50}): defended CI=1.000
throughout; no-defense CI=0.97–0.83, confirming α=0.25 (CI=0.917) is
well-calibrated.

## Web-like IPI Evaluation (full section)

To evaluate IPI on realistic Web content formats, we construct a
40-document Web-like KB (HTML pages, Markdown docs, forum posts, email
threads) with 5 format-specific attack families (HTML comment injection,
Markdown hidden instruction, email footer injection, forum spoiler
injection, meta tag injection), 20 queries, and 3 defense configurations
(300 evaluations, GPT-3.5-turbo).

**Result:** ASR=0% across all 5 attack families and 3 configurations.
CI=1.000, consistent with alignment-governed resistance. However, RD
remains measurably non-zero: No defense RD=0.12–0.28, All heuristic
RD=0.44–0.54, Semantic full RD=0.49–0.59 — mirroring the non-monotonic RD
pattern found elsewhere in this paper. This suggests that, for
GPT-3.5-turbo, evaluated Web-like formats perturb responses without
producing full compromise; RD is a more sensitive indicator than binary
ASR for partial injection effects. Format-specific attacks on less-aligned
models remain future work.
